## ⚠️ 去重机制（每次抓取前必做）

### 问题

同一热点被不同来源多次报道 → 日报重复 → 选题卡重复 → 内容同质化

### 解决方案：三重去重

**第一重：时间窗口去重**

- 7天内已报道的相同话题 → 标记为"跟进"，不作为新热点
- 同一事件的后续发展 → 作为"事件进展"追加到原素材

**第二重：标题指纹去重**

- 提取标题核心词（去掉品牌名/时间词/情绪词）
- 与素材库已有标题比对，相似度>70% → 合并或跳过

**第三重：内容摘要去重**

- 对每篇新文章提取100字摘要
- 与当日已抓取文章摘要比对，重复>50% → 跳过

### 去重执行方式

```
抓取前：
1. 读取 02-热点池/.index/fingerprints.jsonl 最近7天行，检查话题是否已报道
2. 读取 02-热点池/日报/ 目录，检查今日是否已有相同热点

抓取中：
3. 每篇文章抓取后，立即做标题指纹比对
4. 重复 → 合并到原热点文件夹，记录"来源B补充"，跳过
5. 不重复 → 正常入库

抓取后：
6. 最终输出前，再做一次摘要去重
7. 将今日新指纹追加到 02-热点池/.index/fingerprints.jsonl
```

## ⚡ 数据源覆盖率要求（硬性门槛）

### 硬性规则：两层计数，同时满足方为达标

**第一层：独立数据源（实际网络可达性）**

指独立域名/IP 的网站、RSS 源或 API，每成功返回一次有效内容算 1 个。

- `web_search` 合并计为 1 个（不因搜索词多而重复计数）
- tophub.today 的各子频道（微博热搜/知乎热榜等）由 D 类聚合入口统一获取，不单独计数为独立源
- 微信公众号文章：通过 rsshub 或 web_search 获取时算 1 个；纯手工翻公众号不计入自动化覆盖

**第二层：内容领域覆盖（多样性保障）**

Top 15 中涉及的领域类型数。内容极度偏科时，即便第一层达标也应触发多样性补充。

### 独立数据源计数规则


| 来源类型                 | 计为独立源    | 不重复计数         |
| -------------------- | -------- | ------------- |
| 独立域名网站（虎嗅/机器之心等）     | ✅ 每个 1 个 |               |
| RSS 源（数英网/运营派等）      | ✅ 每个 1 个 |               |
| web_search（综合搜索）     | ✅ 合计 1 个 | 不因搜索词多而膨胀     |
| tophub.today（聚合入口）   | ✅ 1 个    | 其子频道不单独计数     |
| tophub 的微博/知乎/B站等子频道 | ❌ 不单独计数  | 由 D 类聚合入口统一覆盖 |


### 覆盖率门槛


| 层级             | 门槛                     | 说明                        |
| -------------- | ---------------------- | ------------------------- |
| **独立数据源（第一层）** | **≥ 6 个**              | 必须为不同域名/RSS/API 的真实可达来源   |
| **领域多样性（第二层）** | **Top 15 中非AI类 ≥ 30%** | AI类 >70% 时降低AI类热点时效性得分10% |
| **近5天内容占比**    | **≥ 60%**              | 过期内容 >40% → 标记数据源失效       |


> ⚠️ **旧门槛"≥17个数据源"已废弃。** 原数字包含了大量实际不可达的 HTML 页面和非独立子频道，无法真实反映抓取能力。
>
> 当前可自动化验证的独立源：tophub.today(1) + 数英网RSS(1) + 运营派RSS(1) + 虎嗅(1) + 机器之心(1) + web_search(1) = **6个**（刚好达标）

### 5天时效性门槛（硬性规则）

> ⚠️ **数据源必须是近5天之内发布的内容，才可作为热点候选。**
>
> - 近5天（含当天）= 发布日期在 `T-5` 至 `T` 之间
> - 超过5天的内容 → 直接丢弃，不进入热点池
> - 无法确认发布时间的来源 → 按抓取时间倒推，超过5天一律丢弃
> - 白皮书/数据报告（B类）→ 例外：发布后30天内有效

### 覆盖率检查点


| 检查节点  | 要求           | 不达标处理                    |
| ----- | ------------ | ------------------------ |
| 抓取开始前 | 确认独立数据源可达    | 不可达的立即启用备用源              |
| 抓取完成后 | 独立数据源 ≥ 6 个  | 启动全部备用源，直到满足 ≥ 6 个       |
| 内容入库前 | 近5天内容占比 ≥60% | 超过40%内容过期 → 报告数据源失效，标记排查 |

## 抓取执行流程

### ⚠️ 前置检查（每次抓取前必须完成）

```
执行前必做检查：
1. [覆盖率] 确认独立数据源可达（不可达的立即启用备用源）
2. [时效性] 设定时间过滤基线：今日 T，往前推 T-5 = 近5天
3. [去重] 读取 02-热点池/.index/fingerprints.jsonl 最近7天行，检查话题是否已报道
4. [记录] 记录本次覆盖的独立数据源数量，低于6个不得进入后续流程

⚠️ 硬性门槛：独立数据源数 < 6 → 立即启动全部备用源 → 重新验证
```

### Step 0：每日必查 — 平台官方动态（每日上班第一件事）

**执行顺序：先官方，后热榜，再垂直媒体。**

```
平台官方动态抓取：
1. 微信搜索「小红书商业动态」→ 读取最新文章
2. 微信搜索「微信公开课」→ 读取最新文章
3. 检查是否有规则/算法/功能更新
4. 如有重大更新 → 立即生成选题卡（优先 P3 方法论型）

判断标准：
- 新规发布 → 选题方向：「官方明确了，XX 以后这样做」
- 数据报告 → 选题方向：「基于 XX 数据，XX 趋势正在发生」
- 案例分享 → 选题方向：「小红书官方推荐的 XX 品牌是怎么做的」
```

### Step 1：检查去重记录 & 时效性基线（每日首次抓取前）

```
检查顺序：
1. 02-热点池/.index/fingerprints.jsonl 最近7天行   ← 标题指纹索引（优先）
2. 02-热点池/日报/今日热点简报-YYYY-MM-DD.md        ← 今日已入库热点
3. 02-热点池/日报/热点最终筛选-YYYY-MM-DD.md         ← 已入选题热点

时效性基线设定：
- 今日日期 T，往前推 T-5（5天内）
- 任何内容发布日期 > T-5 → 丢弃，不进入热点池
- 无发布日期且无抓取时间戳 → 丢弃
- 白皮书（B类）→ 发布后30天内有效
```

### Step 5：逐篇正文抓取 & 时间过滤

对每个来源的文章列表，提取正文内容，同时完成时效性过滤：

```bash
# 示例：抓取数英网文章正文
python3 fetch_article.py \
  --url "https://www.digitaling.com/articles/XXXXX.html" \
  --min_words 300 \
  --max_age_days 5 \
  --output "/path/to/02-热点池/原始素材/YYYY-MM-DD/[来源]-[文章ID].md"
```

**质量门槛（双重过滤）：**


| 维度   | 门槛         | 不达标处理      |
| ---- | ---------- | ---------- |
| 正文字数 | < 300字     | 丢弃         |
| 内容类型 | 列表页/聚合页    | 丢弃         |
| 内容时效 | 发布时间 > T-5 | 丢弃（标记过期来源） |
| 内容重复 | 摘要相似度>50%  | 合并或跳过      |


**⚠️ 时效性强制过滤：**

- 每篇文章抓取后，立即检查 `publish_date` 字段
- `publish_date` 早于 T-5 → 不写入素材库，记录丢弃原因
- 无 `publish_date` 但有 `crawl_date`：若 `crawl_date - article_date > 5天` → 丢弃
- 白皮书（B类）特殊处理：`publish_date` 在30天内 → 放行；否则 → 丢弃

### Step 6：覆盖率验收 & 去重合并

```python
# 覆盖率验收 + 去重逻辑伪代码
def process_article(new_article):
    # ── 时效性过滤（第一关）────────────────────────────
    days_old = (today - new_article.publish_date).days
    if new_article.category == "B类_白皮书":
        if days_old > 30:
            return "SKIP_EXPIRED"      # 白皮书30天过期
    else:
        if days_old > 5:
            return "SKIP_EXPIRED"      # 普通内容5天过期

    # ── 覆盖率计数 ───────────────────────────────────
    count_source(new_article.source_name)  # 记录有效数据源

    # ── 去重（第二关）───────────────────────────────
    title_fingerprint = extract_fingerprint(new_article.title)
    if title_fingerprint in existing_fingerprints:
        append_to_existing(new_article, existing_id)
        return "MERGED"

    summary = extract_summary(new_article.content, 100)
    if is_duplicate(summary, today_summaries):
        return "SKIP_DUPLICATE"

    if is_same_topic(new_article, last_7_days):
        return "FOLLOW_UP"

    return "NEW"

# ── 覆盖率验收 ────────────────────────────────────
def check_coverage():
    active_sources = get_active_source_count()
    if active_sources < 6:
        print(f"⚠️ 覆盖率不足：当前 {active_sources}/6，启动全部备用源")
        activate_backup_sources()
        while get_active_source_count() < 6:
            activate_backup_sources()
            if no_more_sources():
                raise Exception("无法达到6个独立数据源覆盖率，停止本次抓取")
    print(f"✅ 覆盖率达标：{get_active_source_count()}/6")
```

## 筛选标准

### 时效性门槛（硬性过滤，非评分）

> ⚠️ **进入筛选池的内容，必须是近5天之内发布的。**
>
> - 时效性过滤先于评分执行
> - 发布日期 > T-5 的内容，直接排除，不参与任何评分
> - 白皮书（B类）：发布后30天内有效

### 自动过滤


| 维度     | 门槛         | 处理方式           |
| ------ | ---------- | -------------- |
| 时效性    | 发布日期 > T-5 | 丢弃（标记：EXPIRED） |
| 正文字数   | < 300字     | 丢弃             |
| 内容类型   | 列表页/首页/聚合页 | 丢弃             |
| 内容重复   | 摘要相似度>50%  | 跳过             |
| 7天话题重复 | 相同话题       | 标记"跟进"，不重复入库   |


### AI评分（保留Top 15）

> ⚠️ **前提：内容已通过时效性门槛（近5天内发布）**


| 维度        | 权重      | 说明                           |
| --------- | ------- | ---------------------------- |
| **时效性**   | **30%** | **24h内爆发话题优先；5天内但接近5天边界的递减** |
| **官方权威性** | **20%** | **平台官方发布的内容权重最高，直接进入 Top 5** |
| 客户关联      | 20%     | 能服务≥1个客户的热点优先                |
| 多平台适配     | 15%     | 能转化为≥2个平台的内容优先               |
| 素材丰富度     | 15%     | 有≥3个高质量来源的优先                 |


> ⚠️ **领域多样性惩罚规则：** 若当日 AI 类热点在 Top 15 中占比 >70%，自动降低 AI 类热点的时效性得分 10%，优先保留非AI类热点进入 Top 15。

**时效性评分细则：**


| 发布时间    | 时效性得分    | 说明        |
| ------- | -------- | --------- |
| 0-24小时内 | 100分     | 爆发期，最高权重  |
| 1-2天    | 85分      | 上升期，高权重   |
| 2-3天    | 70分      | 稳定期       |
| 3-4天    | 55分      | 衰减前期      |
| 4-5天    | 40分      | 衰减后期，边界内容 |
| >5天     | 0分（直接排除） | 已过期，不进入评分 |


**平台官方内容特殊规则：**

- 小红书商业动态 / 微信公开课 / 官方公告 → 基础分 95 分以上
- 行业白皮书 / 数据报告 → 基础分 90 分以上
- 这两类内容无论热度如何，优先保留进 Top 15
