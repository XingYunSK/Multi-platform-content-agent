# AI运营内容引擎

> AI驱动、多品牌矩阵运营的全流程内容生产引擎

> 从热点捕捉 → 深度素材 → 选题规划 → 多平台创作 → 配图生成 → 审核发布，全部在 Cursor AI Agent 中自动化执行

---

## 一句话定位

用自然语言驱动 AI Agent 完成代运营公司的整套内容生产流水线，支持**多客户矩阵**、**多平台分发**，零门槛启动。

---

## 核心能力


| 能力          | 说明                           |
| ----------- | ---------------------------- |
| **热点自动抓取**  | 多源采集 → 脱水去重 → 每日简报           |
| **深度素材挖掘**  | 单热点 ≥3 来源交叉验证，构建完整素材支撑       |
| **选题智能规划**  | 选题卡生成 → 分配 → 月度日历            |
| **多平台创作**   | 公众号 / 小红书 / 独立博客，一次热点 N 种表达  |
| **AI 配图生成** | 每篇配图由 gpt-image-2 生成，品牌视觉一致性 |
| **四道审核防线**  | 三层合规 + 质量评分，任何内容不过不发布        |
| **多客户矩阵**   | 同一热点，按品牌规范差异化输出              |


---

## 系统架构

```
热点抓取（SOP-03）
    ↓
深度素材挖掘（SOP-04）
    ↓
选题规划（SOP-05）
    ↓
内容创作（SOP-06） ──── 配图生成（baoyu-article-illustrator）
    ↓
审核发布（SOP-07）
    ↓
数据归档 → 持续优化（用户记忆库）
    ↑
  知识库（客户档案 / 合规风控 / 品牌调性）
```

**依赖关系：**

- 知识库是全流程底层依赖，**任何创作前必须检索**
- 同一热点的多平台内容可并行生成
- 热点脱水与上一热点素材挖掘可并行执行

## 快速开始

### 第一步：安装所需 Skills

本系统依赖 **Cursor Agent Skills**，详见 [SKILLS.md](./docs/SKILLS.md)。

主要需要两个 baoyu skills：

```bash
# 在 Cursor 中打开命令面板
# → "Cursor: Find and Install Agent Skill：https://github.com/JimLiu/baoyu-skills"
# → 搜索并安装以下 Skills：

# baoyu-article-illustrator
#    文章配图生成：分析文章结构 → 生成配图提示词 → 调用 gpt-image-2 出图
```

> baoyu skills 列表及安装方式详见 [SKILLS.md](./docs/SKILLS.md)

### 第二步：配置品牌知识库

至少完成一个客户的档案配置：

```bash
# 创建客户档案
01-知识库/01-客户档案库/[你的客户名]/
  ├── 品牌规范.md          # 必填：品牌调性/核心卖点/禁忌
  ├── 产品矩阵.md          # 产品线/定价/目标人群
  └── 人群画像.md          # 核心受众描述
```

### 第三步：开始今日工作流

打开 Cursor，在当前仓库中直接对话：

```
帮我开始今日SOP
```

AI Agent 将自动：

1. 读取今日热点简报
2. 执行深度素材挖掘
3. 筛选选题并生成选题卡
4. 输出今日工作清单

## 核心原则

> **合规优先** — 任何内容必须通过全部审核防线，不得跳过  
> **RAG 防幻觉** — AI 写作前必须检索客户知识库，禁止空凭想象  
> **多客户矩阵** — 同一热点，多品牌差异化表达  
> **数据驱动** — 发布数据持续回流，优化选题策略

## 项目说明

这是一个以 Markdown 文件和 Obsidian 工作区为核心的内容运营操作系统。它把“研究、判断、生产、审核、发布、复盘”拆成可追踪的文件资产，并通过 SOP 与 Prompt 约定 Agent 的执行顺序。仓库本身不包含独立后端或前端服务，打开 Obsidian 或在 Cursor 等支持 Agent Skills 的编辑器中即可使用。

### 推荐使用方式

1. 用 Obsidian 打开仓库根目录，并确认已启用需要的社区插件。
2. 先完成 `01-知识库/01-客户档案库/` 中的品牌资料，再运行每日 SOP。
3. 每次产出按“热点 → 选题 → 草稿 → 审核 → 发布”归档，避免覆盖历史版本。
4. 将真实发布数据和复盘结论补回 `01-知识库/04-用户记忆库/`，形成下一轮选题依据。

### 数据与隐私

仓库中的客户档案、运营记录和草稿可能包含业务机密。公开到 GitHub 前，请检查客户名称、内部链接、联系方式、API Key 和本地配置；敏感信息应使用占位符或移出仓库。`.gitignore` 已默认排除 macOS 元数据、环境变量和本地编辑器状态。

### 版本约定

- `main` 保存可复用的 SOP、模板和经过整理的内容资产。
- 日常工作按日期建立目录，原始素材、分析结果和发布稿分别保存。
- 提交信息建议使用 `docs:`、`feat:`、`fix:` 等前缀，并在正文说明影响范围。
